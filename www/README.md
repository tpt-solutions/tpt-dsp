# Web Guitar Pedalboard

A browser-front end for [`tpt-dsp`](../tpt-dsp-wasm), built with `wasm-bindgen`
and the Web Audio `AudioWorklet` API. The signal chain is
`distortion → delay → reverb → EQ`, running entirely in WebAssembly with no
heap allocation inside the 128-sample render quantum (proved by the
`process_block_128_does_not_allocate` test in `tpt-dsp-wasm`).

## Layout

| File | Purpose |
| --- | --- |
| `index.html` | Pedalboard UI (sliders for drive, delay, reverb, EQ). |
| `main.js` | Bootstrap: compiles the wasm module, loads the worklet, wires controls. |
| `pedal-processor.js` | The `AudioWorkletProcessor` that drives the Rust `Pedalboard`. |
| `pkg/` | Generated by `wasm-pack` (see below). **Not** committed. |

## Build

Requires [`wasm-pack`](https://rustwasm.github.io/wasm-pack/):

```powershell
wasm-pack build tpt-dsp-wasm --target web --out-dir ../www/pkg
```

This produces `www/pkg/tpt_dsp_wasm.js` and `www/pkg/tpt_dsp_wasm_bg.wasm`,
which `main.js` and `pedal-processor.js` import.

## Run locally

The page must be served over HTTP (ES modules and `AudioWorklet` do not work
from `file://`). Any static server works:

```powershell
# Python
python -m http.server 8080 --directory www
# or Node
npx serve www
```

Open <http://localhost:8080>, click **Start (microphone)** (grant access when
prompted) or **Start (demo tone)**, and play. Adjust the pedals live; the
changes arrive as messages to the worklet and update the Rust state without
allocating in the audio path.

## Deploy

The `Deploy web pedalboard to Pages` GitHub Actions workflow builds the wasm
package and publishes this `www/` directory to GitHub Pages on every push to
the default branch. No extra configuration is needed beyond enabling Pages in
the repository settings (source: *GitHub Actions*).
